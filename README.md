# VEKEC LMS — วิทยาลัยเทคนิคกำแพงเพชร

ระบบศูนย์การศึกษาอาชีพออนไลน์ภาษาไทยสำหรับ ปวช. ปวส. และประชาชนทั่วไป ใช้ **PHP 8.3 OOP + MySQLi + MySQL 8.4 + jQuery 4 + CSS** รันด้วย Docker และ Apache แยกข้อมูลถาวรออกจากคอนเทนเนอร์

## ข้อเสนอออกแบบ AI สำหรับครูผู้สอน

ดู [เอกสารออกแบบ AI API](docs/ai-teacher-api-design.md) และ [สเปก OpenAPI 3.1](docs/ai-teacher-api.openapi.json) ครอบคลุมสร้างเนื้อหา ข้อสอบ/ใบงาน วิดีโอเสียงไทย ผู้ช่วยสอน และวิเคราะห์ผลการเรียน พร้อมแนวทางเก็บเวอร์ชันหลักสูตร

**พัฒนาแล้ว:** ระบบ BYOK ของครู `/teach/ai-connections`, ผู้ดูแลจัดการ provider/model ที่ `/admin/ai-providers` และ AI ช่วยร่าง **บทเรียน ใบงาน และข้อสอบปรนัย** ในหน้าจัดการรายวิชา/คลังข้อสอบ ครูตรวจและแก้ก่อนนำลงแบบฟอร์มหรือบันทึก ใช้ provider/model/แหล่งจ่ายและงบ `text` เดิม รองรับ OpenAI-compatible, Anthropic และ Gemini **ไม่เปิด AI ให้นักศึกษา** และเคารพการล็อกหลักสูตรที่มีผู้เรียนแล้ว

ดู [ติดตั้ง BYOK](docs/ai-byok-setup.md) และ [ติดตั้ง/ใช้งาน AI สร้างฉบับร่าง](docs/ai-drafts-setup.md) ต้องรัน migration ถึง `008_ai_drafts` และตั้งราคา Input/Output ของโมเดลจากหน้า Admin ผู้ให้บริการ AI ก่อนเรียก generation (`AI_TEXT_PRICING_JSON` เป็นทางเลือกสำรอง) การทดสอบใช้ provider จำลอง ไม่มีการใช้ key จริง ส่วนวิดีโอ ผู้ช่วยสอน วิเคราะห์ผล และเวอร์ชันหลักสูตรยังเป็นแบบออกแบบ

## เปิดใช้งานในเครื่อง

เว็บไซต์: **http://localhost:8088**

โปรเจกต์นี้เตรียม `.env` ด้วยรหัสผ่านสุ่มไว้แล้ว โดยไม่ได้แสดงข้อมูลลับในแชต เปิดไฟล์นี้ใน IDE เพื่อดู `ADMIN_EMAIL` และ `ADMIN_PASSWORD` สำหรับเข้าสู่ระบบผู้ดูแล

```sh
docker compose up -d --build
docker compose exec -T web php bin/migrate.php
docker compose exec -T web php bin/setup.php
```

`bin/setup.php` สร้างผู้ดูแลครั้งแรก และไม่เปลี่ยนรหัสผ่านของบัญชีที่มีอยู่แล้ว หากเริ่มจาก source ใหม่ ให้คัดลอก `.env.example` เป็น `.env` และตั้ง `APP_KEY`, รหัสผ่านฐานข้อมูล และรหัสผ่านผู้ดูแลก่อนรัน ห้ามนำค่า `replace-...` ไปใช้จริง `APP_KEY` ควรเป็นค่าสุ่มอย่างน้อย 32 ไบต์และต้องเก็บสำรองอย่างปลอดภัย

คำสั่งสำหรับตัวอย่างรายวิชา (เฉพาะ `APP_ENV=local`):

```sh
docker compose exec -T web php bin/demo.php
```

ในเครื่องนี้มีตัวอย่าง 4 รายวิชา ระบุคำว่า “รายวิชาตัวอย่างสำหรับทดสอบระบบ” ชัดเจน ไม่ใช่หลักสูตรที่วิทยาลัยรับรองแล้ว ผู้ดูแลแก้ไขหรือปิดรับสมัครได้ บัญชีผู้สอนตัวอย่างไม่มีรหัสผ่าน จึงเข้าสู่ระบบไม่ได้

```sh
docker compose ps
docker compose logs --tail=50 web
docker compose stop
```

ข้อมูลอยู่ใน Docker volumes `vekec-lms_database` และ `vekec-lms_uploads` การหยุด/สร้างคอนเทนเนอร์ใหม่ไม่ลบข้อมูล **อย่าใช้ `down -v` กับระบบใช้งานจริง** หากต้องการเก็บข้อมูลไว้

## ฟังก์ชัน

| ส่วนงาน | ความสามารถ |
| --- | --- |
| บุคคลทั่วไป | ค้นหารายวิชา กรองหมวด/ระดับ ดูรายละเอียดและหัวข้อก่อนสมัคร |
| บัญชีผู้ใช้ | สมัครอีเมล เข้าสู่ระบบ เปลี่ยนข้อมูลและรหัสผ่าน การเชื่อมต่อ ThaID |
| ผู้เรียน | ลงทะเบียน เรียนตามลำดับ ดูวิดีโอ ส่งใบงาน สอบ ดูคะแนนและความคืบหน้า |
| ครู | สร้าง/แก้ข้อมูลรายวิชา เปิด/ปิดรับสมัคร เพิ่ม/ลบบทเรียนก่อนมีผู้เรียน สร้างข้อสอบ นำเข้า CSV/JSON |
| จัดชั้นเรียน | ครูสร้างบัญชีและลงทะเบียนให้ผู้เรียน หรือเพิ่มผู้เรียนที่มีบัญชีแล้ว ตรวจงาน ให้คะแนน และดูผลรายกิจกรรม |
| ผู้ดูแล | จัดการทุกรายวิชาและหมวดหมู่ เพิ่ม/แก้ไข/ลบ/นำเข้าสมาชิก เปลี่ยนบทบาท เปิด/ระงับบัญชี ออกแบบเกียรติบัตร/เพิ่มลายเซ็น ตั้งค่าระบบ ดู audit log |
| ใบประกาศ | ออกเมื่อเรียนครบและผ่านทุกกิจกรรม พิมพ์/บันทึก PDF ผ่านเบราว์เซอร์ มีเลขอ้างอิงและหน้าตรวจสอบ |

ผู้สมัครด้วยตนเองจะได้สิทธิ์ผู้เรียนเสมอ ผู้ดูแลสร้างหรือนำเข้าบัญชีครูได้โดยตรง หรือเปลี่ยนบทบาทของบัญชีเดิมใน **จัดการระบบ → บัญชีผู้ใช้งาน** ผู้สอนไม่สามารถอ่านข้อมูลหรือให้คะแนนในรายวิชาของครูคนอื่นได้

### จัดการบัญชีผู้ใช้งาน

ผู้ดูแลเปิด **จัดการระบบ → บัญชีผู้ใช้งาน** ที่ `/admin#users`

- **เพิ่มสมาชิก:** กด “เพิ่มสมาชิก” กรอกชื่อ–นามสกุล อีเมล รหัสผ่าน บทบาท ระดับผู้เรียน และสถานะ บัญชีที่เปิดใช้งานสามารถเข้าสู่ระบบได้ทันที ผู้ดูแลสร้างบัญชีได้แม้ปิดรับสมัครทั่วไป
- **แก้ไข:** กด “แก้ไข” ในแถวสมาชิก เปลี่ยนชื่อ อีเมล บทบาท ระดับ และสถานะได้ รหัสผ่านใหม่เว้นว่างเพื่อคงรหัสเดิม ชื่อบนใบประกาศที่ออกแล้วไม่เปลี่ยน และประวัติการเรียนยังอยู่
- **ลบ:** กด “ลบ” แล้วเลือกช่องยืนยันในหน้าตรวจสอบ ลบได้เฉพาะบัญชีที่ไม่มีรายวิชา ประวัติลงทะเบียน ความคืบหน้า การสอบ การส่งงาน/ให้คะแนน ใบประกาศ หรือภาพบทเรียนที่อ้างอิงอยู่ หากมีข้อมูลเหล่านี้ ระบบจะแสดงจำนวนรายการและลิงก์แก้ไขสถานะเพื่อระงับบัญชีแทน การลบและการระงับทำให้เซสชันเดิมเข้าใช้งานต่อไม่ได้
- **นำเข้าสมาชิก:** กด “นำเข้าสมาชิก” ดาวน์โหลดตัวอย่าง [CSV](public/templates/members.csv) หรือ [JSON](public/templates/members.json) แทนที่ข้อมูลตัวอย่างและกำหนดรหัสผ่านเฉพาะของแต่ละคน แล้วอัปโหลด สูงสุด **200 สมาชิก / 1 MB ต่อครั้ง** สำหรับ Excel ให้บันทึกเป็น **CSV UTF-8 (คั่นด้วยจุลภาค)** ก่อน ไม่รับ `.xlsx` โดยตรง

รูปแบบไฟล์ใช้คอลัมน์/ฟิลด์ตามตาราง CSV สลับลำดับคอลัมน์ได้ รองรับ UTF-8 BOM ภาษาไทย เครื่องหมายคำพูด และจุลภาคในช่องที่ครอบด้วยเครื่องหมายคำพูด JSON เป็นอาร์เรย์ของข้อมูลสมาชิก

| ฟิลด์ | ข้อมูล |
| --- | --- |
| `name` | จำเป็น: ชื่อ–นามสกุล 1–180 ตัวอักษร |
| `email` | จำเป็น: อีเมลที่ไม่ซ้ำ ทั้งในระบบและในไฟล์ โดยไม่แยกตัวพิมพ์เล็ก/ใหญ่ |
| `password` | จำเป็น: รหัสผ่าน 12–72 ไบต์ เก็บในฐานข้อมูลเป็นแฮชเท่านั้น |
| `role` | `student`, `teacher`, `admin`; ไม่ระบุหรือเว้นว่างใช้ `student` |
| `level` | `public`, `voc1`, `voc2`; ไม่ระบุหรือเว้นว่างใช้ `public` |
| `active` | `1` = ใช้งาน, `0` = ระงับ; ไม่ระบุหรือเว้นว่างใช้ `1`; JSON รองรับ boolean ด้วย |

การนำเข้าสร้างเฉพาะบัญชีใหม่ ไม่แก้ไขบัญชีที่มีอีเมลอยู่แล้วและไม่ลงทะเบียนรายวิชาให้อัตโนมัติ ระบบตรวจทั้งไฟล์และบันทึกใน transaction เดียว หากพบข้อผิดพลาดหรืออีเมลซ้ำจะยกเลิกทั้งชุด พร้อมระบุแถว CSV หรือรายการ JSON ที่ต้องแก้ไข ไฟล์ต้นฉบับและรหัสผ่านไม่ถูกเก็บใน audit log

ผู้ดูแลไม่สามารถลบ ระงับ หรือเปลี่ยนบทบาทของตนเองได้ บัญชีที่เป็นเจ้าของรายวิชายังเปลี่ยนเป็นผู้เรียนไม่ได้ บัญชี ThaID แก้ไขระดับ บทบาท และสถานะได้ โดยคงชื่อ อีเมล และวิธียืนยันตัวตนเดิมไว้ ทุกการเพิ่ม แก้ไข ลบ รีเซ็ตรหัสผ่าน และนำเข้าสมาชิกมี audit log

ฟังก์ชันนี้ใช้ตาราง `users` เดิม จึงไม่ต้องเพิ่ม migration สำหรับฐานข้อมูลที่อัปเดต schema ของระบบแล้ว

### ออกแบบเกียรติบัตรและลายเซ็น

ผู้ดูแลเปิด **ออกแบบเกียรติบัตร** จากเมนูด้านซ้าย หรือ **จัดการระบบ → ออกแบบเกียรติบัตร** ที่ `/admin/certificate-design`

- เลือกกรอบ **คลาสสิก / ร่วมสมัย / เรียบง่าย** และสีหลัก หรือเลือกสีจากชุดสีแนะนำ
- แก้ชื่อสถานศึกษา หัวเรื่อง หัวเรื่องรอง ข้อความก่อนชื่อผู้รับ และข้อความรับรอง เลือกแสดง/ซ่อนจำนวนชั่วโมงเรียนได้
- ระบุ **ชื่อ–นามสกุลผู้อำนวยการ** และ **ตำแหน่ง** แยกช่องกัน
- อัปโหลดลายเซ็น **PNG / JPG / WebP ไม่เกิน 2 MB และ 8 ล้านพิกเซล** แนะนำ PNG พื้นหลังโปร่งใสที่ตัดขอบว่างแล้ว ระบบตรวจชนิดและข้อมูลภาพจริง ไม่รับ SVG หรือไฟล์ปลอม
- เลือกตำแหน่งผู้ลงนาม **ซ้าย / กลาง / ขวา** และปรับขนาดภาพลายเซ็นได้ 12–30% ของความกว้างเกียรติบัตร ไม่เลือกไฟล์ใหม่จะใช้ลายเซ็นเดิม เลือก “นำลายเซ็นออกจากแม่แบบ” เพื่อนำออกจากใบที่จะออกใหม่
- ภาพตัวอย่างเปลี่ยนตามข้อมูลที่กำลังแก้ไข กด **บันทึกแม่แบบเกียรติบัตร** เพื่อนำไปใช้ จากนั้นกด **ดูแบบที่บันทึก / พิมพ์** เพื่อตรวจตัวอย่าง A4 แนวนอนหนึ่งหน้า และพิมพ์หรือบันทึกเป็น PDF ผ่านเบราว์เซอร์ หากมีวันที่/URL ของเบราว์เซอร์บนกระดาษ ให้ปิด Headers and footers ในหน้าต่างพิมพ์

ชื่อผู้รับ ชื่อรายวิชา จำนวนชั่วโมง วันที่ และเลขอ้างอิงใช้ข้อมูลจริงในขั้นตอนออกเกียรติบัตร หน้าตัวอย่างระบุชัดเจนว่าเป็นตัวอย่าง และไม่ได้สร้างเกียรติบัตรให้ผู้เรียน การรับเกียรติบัตรจริงยังต้องเรียนครบและผ่านทุกกิจกรรมตามเงื่อนไขเดิม

**การแก้แม่แบบมีผลกับใบที่ออกใหม่เท่านั้น** แต่ละใบเก็บแม่แบบ ข้อความ ชื่อผู้ลงนาม ตำแหน่ง และภาพลายเซ็น ณ วันออกใบไว้ใน `certificates.design_snapshot` การเปลี่ยนชื่อ เปลี่ยนภาพ หรือนำลายเซ็นออกจากแม่แบบจะไม่เปลี่ยนใบเดิม รวมถึงการขอรับใบซ้ำ เกียรติบัตรที่ออกก่อนมีหน้าออกแบบจะใช้รูปแบบเดิมต่อไป และการออกใบก่อนบันทึกแม่แบบครั้งแรกยังคงใช้ข้อมูลสถานศึกษา/ผู้รับรองเดิม

ภาพลายเซ็นอยู่ใน private storage ผู้ดูแลดูภาพของแม่แบบได้ ส่วนภาพบนใบที่ออกแล้วเข้าถึงผ่านสิทธิ์เจ้าของใบ/ผู้ดูแล หรือเลขอ้างอิงในหน้าตรวจสอบสาธารณะเช่นเดียวกับเกียรติบัตร ภาพเก่าจะถูกเก็บไว้สำหรับใบเดิม ทุกการบันทึกแม่แบบ เพิ่ม หรือเอาลายเซ็นออกมี audit log

อัปเดตฐานข้อมูลเดิมด้วย `docker compose exec -T web php bin/migrate.php` สคริปต์ `003_certificate_design` เพิ่มคอลัมน์ snapshot โดยไม่แก้เกียรติบัตรเดิมและรันซ้ำได้ ระบบ local ใน workspace นี้อัปเดตแล้ว สำหรับ production ให้ rebuild image และรัน migration ด้วย `compose.production.yaml` ตามขั้นตอนติดตั้ง

### จัดการหมวดหมู่

ผู้ดูแลเปิด **จัดการหมวดหมู่** จากเมนูด้านซ้าย หรือ **จัดการระบบ → หมวดหมู่รายวิชา** ที่ `/admin/categories`

- **เพิ่ม:** กรอกชื่อ 1–100 ตัวอักษร ชื่อต้องไม่ซ้ำ รายการใหม่จะแสดงในหน้าสร้าง/แก้ไขรายวิชาและตัวกรองค้นหาทันที
- **แก้ไข:** เปลี่ยนชื่อแล้วกดบันทึก ระบบอัปเดตชื่อในรายวิชาที่เกี่ยวข้องทั้งหมด รวมฉบับร่างและรายวิชาที่ปิดรับสมัคร
- **ลบ:** เปิด “ลบหมวดหมู่” แล้วกดยืนยัน หากมีรายวิชาอยู่ต้องเลือกหมวดหมู่ปลายทาง ระบบจะย้ายรายวิชาและลบหมวดหมู่ใน transaction เดียว โดยเก็บเนื้อหา ผู้เรียน ความคืบหน้า และใบประกาศไว้
- ครูเลือกหมวดหมู่จากรายการกลาง ผู้ดูแลเท่านั้นที่เพิ่ม แก้ไข และลบหมวดหมู่ได้

สำหรับฐานข้อมูลที่สร้างก่อนมีฟังก์ชันนี้ ให้รัน `docker compose exec -T web php bin/migrate.php` หลังอัปเดต source โดยไม่ลบ volume สคริปต์สร้างตารางและนำหมวดหมู่ที่ใช้ในรายวิชาเดิมเข้าระบบ รันซ้ำได้และไม่สร้างหมวดหมู่ที่ผู้ดูแลลบไปแล้วกลับมาอีก

### หน้าแรกและการค้นหารายวิชา

หน้าแรกแสดง **รายวิชาใหม่ล่าสุด 3 วิชา** เรียงจากวันที่สร้าง และ **รายวิชาที่มีผู้สนใจเรียนมากที่สุด 3 อันดับ** เรียงจากจำนวนผู้ลงทะเบียนเรียนจริง พร้อมแสดงอันดับและยอดผู้ลงทะเบียน ทั้งสองส่วนแสดงเฉพาะรายวิชาที่เปิดรับสมัคร หากจำนวนเท่ากันจะเรียงรายวิชาที่สร้างใหม่ก่อน และหากมีไม่ถึง 3 วิชาจะแสดงเท่าที่มี

ส่วนค้นหารายวิชาใช้ dropdown **แผนกวิชา** จากรายการหมวดหมู่ที่ผู้ดูแลจัดการ เลือก “รายวิชาทั้งหมด · ทุกแผนกวิชา” เพื่อยกเลิกตัวกรองได้ เมื่อเปลี่ยนแผนก ระบบค้นหาให้อัตโนมัติโดยคงคำค้นหาและระดับผู้เรียนไว้ ปุ่มค้นหายังใช้งานได้เมื่อปิด JavaScript ส่วนรายวิชาใหม่และยอดนิยมแสดงภาพรวมของระบบโดยไม่ขึ้นกับตัวกรองค้นหา

### ตารางและการแบ่งหน้า

ตารางจัดการรายวิชา รายชื่อผู้เรียน บัญชีผู้ใช้ ประวัติการจัดการ รวมถึงรายการสาขาวิชา/หมวดหมู่และงานที่ส่ง มีปุ่มก่อนหน้า/ถัดไป เลขหน้า และจำนวนรายการรวม เลือกแสดงได้ **10, 25 หรือ 50 รายการต่อหน้า** ค่าเริ่มต้น 10 รายการ

ระบบอ่านข้อมูลเฉพาะหน้าที่เลือกจากฐานข้อมูลด้วย `LIMIT/OFFSET` คำค้นหาและการตั้งค่าของตารางอื่นยังคงอยู่เมื่อเปลี่ยนหน้า ตารางบัญชีผู้ใช้กับประวัติการจัดการ และตารางผู้เรียนกับรายการงานที่ส่ง ใช้เลขหน้าแยกจากกัน หากเลขหน้าเกินจำนวนข้อมูลจะปรับไปหน้าสุดท้าย รายการปลายทางสำหรับย้ายสาขาวิชา/หมวดหมู่ยังเลือกได้ครบทุกหน้า

### รายวิชาและการเรียน

1. ครูสร้างรายวิชา เลือกระดับ จำนวนชั่วโมง และการบังคับเรียนตามลำดับ
2. เพิ่มบทเรียน/เอกสาร, วิดีโอ, ใบงานที่ครูตรวจ หรือข้อสอบปรนัยตรวจอัตโนมัติ
3. แบบทดสอบต้องมีอย่างน้อย 1 ข้อก่อนเปิดรับสมัคร กำหนดคะแนนผ่าน เวลาสอบ และจำนวนครั้งที่ทำได้
4. เมื่อเปิดรับสมัคร ผู้เรียนจะลงทะเบียนได้เฉพาะระดับที่ตรงกันหรือรายวิชาสำหรับทุกระดับ
5. ครูตรวจใบงานในหน้าผู้เรียนของรายวิชา คะแนนผ่านจะปลดล็อกกิจกรรมถัดไป ผู้เรียนส่งใหม่ได้เมื่อยังไม่ผ่าน
6. เมื่อผ่านครบทุกกิจกรรม ผู้เรียนกดรับใบประกาศจากหน้ารายวิชาได้ การออกซ้ำคืนเอกสารเดิม

โครงสร้างบทเรียนและข้อสอบจะล็อกเมื่อมีผู้ลงทะเบียน เพื่อรักษาประวัติการเรียนและผลสอบ ครูยังแก้ข้อมูลแนะนำรายวิชา ตรวจงาน และปิดรับสมัครได้ หากต้องเปลี่ยนโครงสร้างหลักสูตรให้สร้างรายวิชารุ่นใหม่ การเปลี่ยนคะแนนหลังออกใบประกาศถูกปฏิเสธ

### วิดีโอและไฟล์

- MP4 อัปโหลดได้สูงสุด 256 MB; เอกสาร/ใบงาน PDF, JPG, PNG สูงสุด 10 MB
- MP4 ที่อัปโหลดตรวจ MIME และอ่านความยาวจริงด้วย `ffprobe` ฝั่งเซิร์ฟเวอร์
- วิดีโอภายนอกรองรับลิงก์ HTTPS; การติดตามบังคับดูรองรับ MP4 โดยตรงและ YouTube ให้ครูกรอกจำนวนวินาทีให้ตรงกับวิดีโอจริง
- ผู้ให้บริการวิดีโออื่นเปิดเป็นลิงก์ภายนอก และไม่รองรับการบังคับดูอัตโนมัติ
- MP4 ภายนอกต้องอนุญาตให้เบราว์เซอร์เล่นได้ และ YouTube ต้องอนุญาต embed
- วิดีโอบังคับดูจำกัดการข้ามช่วงและความเร็ว ส่ง heartbeat ทุก 5 วินาที เซิร์ฟเวอร์ตรวจลำดับเวลา/ตำแหน่งและเงื่อนไขผ่านก่อนปลดล็อก บันทึกได้เมื่อเหลือไม่เกิน 2 วินาทีและดูอย่างน้อย 95% เพื่อรองรับความคลาดเคลื่อนของ media timestamp
- การติดตามผ่านเบราว์เซอร์ป้องกันการกดข้ามและการส่งเวลาจบแบบทันทีได้ แต่ไม่ใช่หลักฐานว่าบุคคลกำลังมองหน้าจอ และไม่ใช่ระบบคุมสอบหรือ DRM
- ไฟล์เก็บนอก web root ให้บริการผ่านเส้นทางที่ตรวจสิทธิ์และรองรับ HTTP Range

### ตัวแก้ไขข้อความและรูปภาพ

หน้า **จัดการรายวิชา → เพิ่มกิจกรรมการเรียนรู้** มีตัวแก้ไขในช่องเนื้อหา/คำชี้แจง ใช้สร้างบทเรียน ใบงาน แบบฝึกหัด และคำชี้แจงข้อสอบได้ ส่วนหน้า **ข้อสอบ → เพิ่มข้อสอบด้วยตัวเอง** มีตัวแก้ไขสำหรับคำถาม ตัวเลือกทั้ง 4 ข้อ และคำอธิบายเฉลย

- จัดหัวข้อ ตัวหนา/เอียง/ขีดเส้นใต้ สีข้อความ สีพื้นหลัง รายการตัวเลข/หัวข้อ จัดแนว ตัวห้อย/ตัวยก ข้อความอ้างอิง ลิงก์ เลิกทำ/ทำซ้ำ และล้างรูปแบบ
- กดปุ่มรูปภาพเพื่อเลือกไฟล์ หรือวาง/ลากรูปลงในเนื้อหา รองรับ JPG, PNG และ WebP ไม่เกิน **5 MB / 20 ล้านพิกเซลต่อภาพ** รูปย่อให้พอดีกับพื้นที่บนมือถือ
- คลิกรูปแล้วกด **Alt** เพื่อเพิ่มคำอธิบายภาพสำหรับโปรแกรมอ่านหน้าจอ ตัวเลือกคำตอบใช้รูปเพียงอย่างเดียวได้
- รูปเก็บในระบบของรายวิชาและตรวจสิทธิ์ทุกครั้งที่เปิด ผู้เรียนเห็นภาพตามลำดับบทเรียน รูปโจทย์แสดงระหว่างทำข้อสอบ และเฉลย/ภาพประกอบเฉลยแสดงเมื่อสอบผ่านหรือใช้สิทธิ์ครบแล้ว หลังสอบผ่านจะไม่เปิดให้สอบซ้ำ
- รูปจากเว็บไซต์ภายนอกหรือ base64 ไม่ถูกบันทึกโดยตรง ให้ใช้ปุ่มอัปโหลดรูป ขณะอัปโหลดระบบจะรอให้เสร็จก่อนยอมให้บันทึกฟอร์ม
- ใช้ [Quill 2.0.3](https://quilljs.com/docs/quickstart) แบบเก็บไฟล์ในโครงการ ไม่มี API key หรือบริการ editor ภายนอก มีการกรอง HTML ฝั่งเซิร์ฟเวอร์ และเก็บข้อความเก่าเป็น plaintext ตามเดิม

ฐานข้อมูลเดิมอัปเดตด้วย `docker compose exec -T web php bin/migrate.php` (migration `002_rich_text_images`) รันซ้ำได้โดยไม่ลบข้อมูล

### รูปแบบไฟล์นำเข้าข้อสอบ

ดาวน์โหลดตัวอย่างที่ `/templates/questions.csv` และ `/templates/questions.json` รูปแบบ CSV ใช้ UTF-8 (มีหรือไม่มี BOM ก็ได้):

```csv
prompt,option_a,option_b,option_c,option_d,answer
ภาษาใดใช้ตกแต่งหน้าเว็บ?,HTML,CSS,SQL,PHP,1
```

```json
[
  {"prompt":"ภาษาใดใช้ตกแต่งหน้าเว็บ?","options":["HTML","CSS","SQL","PHP"],"answer":1}
]
```

`answer`: 0=ก, 1=ข, 2=ค, 3=ง นำเข้า 1–500 ข้อ/ครั้ง ขนาดไม่เกิน 2 MB หากมีข้อผิดพลาดในไฟล์จะไม่บันทึกทั้งชุด การนำเข้าที่สำเร็จเพิ่มข้อใหม่ต่อท้าย ไม่แทนที่ข้อเดิม เฉลยส่งให้ผู้เรียนเมื่อสอบผ่านหรือใช้สิทธิ์ครบแล้ว เวลาใช้เวลาฝั่งเซิร์ฟเวอร์และยังเดินต่อแม้ปิดเบราว์เซอร์

CSV เพิ่มคอลัมน์ `explanation` เป็นคอลัมน์ที่ 7 ได้ และเพิ่ม `content_format` เป็นคอลัมน์ที่ 8 หากต้องการใช้ HTML ส่วน JSON เพิ่มสองฟิลด์นี้ในแต่ละข้อได้ ค่าเริ่มต้นเป็น `text`; ค่า `html` ใช้กับโจทย์ ตัวเลือก และคำอธิบายทั้งหมดในข้อนั้น รูปต้องอ้างอิง `/media/images/...` ของภาพที่อัปโหลดในรายวิชาเดียวกัน (ไม่รองรับนำเข้าไฟล์รูปใน CSV/JSON) ตัวอย่าง HTML อยู่ใน `/templates/questions-rich.json`

## เชื่อมต่อ THA-ID / ThaID

เตรียม OIDC Authorization Code adapter โดยอ้างอิง [ตัวอย่าง PHP ของ ETDA](https://github.com/ETDA/ThaiD-PHP-RP) และใช้ [firebase/php-jwt](https://github.com/googleapis/php-jwt) ตรวจลายเซ็น JWT ด้วย JWKS **ยังไม่ได้ทดสอบยืนยันตัวตนกับบริการจริง** เพราะยังไม่มีค่าการเชื่อมต่อที่ได้รับอนุมัติใน workspace

กำหนดใน `.env` บนเซิร์ฟเวอร์เท่านั้น:

```dotenv
APP_URL=https://vekec.kpt.ac.th
THAID_ENABLED=true
THAID_CLIENT_ID=...
THAID_CLIENT_SECRET=...
THAID_API_KEY=...
THAID_DISCOVERY_URL=https://imauth.bora.dopa.go.th/.well-known/openid-configuration
THAID_REDIRECT_URI=https://vekec.kpt.ac.th/auth/thaid/callback
THAID_SCOPE="...scope ที่ได้รับอนุมัติ..."
THAID_API_KEY_HEADER=...ชื่อ header ตามเอกสารการเชื่อมต่อ...
THAID_PKCE=true
```

API key อย่างเดียวไม่เพียงพอ ต้องมี Client ID, Client Secret, scope และ callback ที่ลงทะเบียนตรงกันด้วย **ชื่อ API-key header, scope และการรองรับ PKCE ต้องตรวจตามเอกสารของ RP ที่ได้รับอนุมัติ** ค่าใน `.env.example` เป็นจุดเริ่มต้นสำหรับตั้งค่า ไม่ใช่การยืนยันค่าของ RP นี้

- ปุ่ม ThaID ปิดไว้จนกว่าจะเปิดและมีข้อมูลลับครบ
- Endpoint ต่าง ๆ อ่านจาก discovery และจำกัด HTTPS/host ที่กำหนดไว้ ไม่ตาม redirect ของการเรียก token
- ตรวจ `state` แบบใช้ครั้งเดียว อายุ 10 นาที, `nonce`, issuer, audience, azp, exp, iat, subject และลายเซ็น RSA/RS256
- ส่ง PKCE S256 เมื่อเปิดใช้งาน หาก discovery ไม่ระบุรองรับ ระบบปฏิเสธการเริ่ม flow ให้ตรวจเอกสาร RP ก่อนตั้ง `THAID_PKCE=false`
- ไม่เก็บ access token, ID token หรือเลขบัตรประชาชนลงฐานข้อมูล บัญชีใช้ HMAC ของ issuer+subject เป็นตัวเชื่อมโยง อย่าเปลี่ยน `APP_KEY` โดยไม่มีแผนย้าย subject hashes
- ไม่ผูกบัญชีอีเมลเดิมกับ ThaID อัตโนมัติ บัญชีจาก ThaID เริ่มที่ระดับประชาชนทั่วไป ให้ผู้เรียนเลือกระดับก่อนสมัครเรียนครั้งแรก
- Callback ถูกยกเว้นจาก Apache access log และมีตัวอย่างการปิด log ใน reverse proxy เพื่อไม่เก็บ authorization code

หลังเปลี่ยน `.env` ให้ recreate web container แล้วทดสอบบนโดเมน callback จริงทั้งการอนุญาต ยกเลิก หมดอายุ และการเข้าสู่ระบบซ้ำ

## ติดตั้งบน https://vekec.kpt.ac.th

โปรเจกต์นี้ใช้ PHP/MySQL แบบ Docker ไม่สามารถนำ PHP ไปประมวลผลบน Sites/Cloudflare Workers ได้โดยตรง จึงเตรียมการรันบนเซิร์ฟเวอร์ของวิทยาลัย ไม่ได้เผยแพร่หรือเปลี่ยน DNS ของโดเมนจริง

1. นำ source ไปไว้บนเซิร์ฟเวอร์ที่ติดตั้ง Docker Compose และตั้ง `.env` ใหม่ด้วยข้อมูล production; ตั้ง `APP_URL=https://vekec.kpt.ac.th` และรหัสผ่านแบบสุ่ม
2. ชี้ DNS ไปเซิร์ฟเวอร์ และติดตั้ง TLS certificate ที่ถูกต้อง
3. เริ่มบริการด้วยไฟล์ production ซึ่งใช้โค้ดจาก image ไม่มี source bind mount:

   ```sh
   docker compose -f compose.production.yaml up -d --build
   docker compose -f compose.production.yaml exec -T web php bin/migrate.php
   docker compose -f compose.production.yaml exec -T web php bin/setup.php
   ```

4. ตั้ง reverse proxy จากตัวอย่าง `docker/nginx.example.conf` แล้วตรวจ config/reload ด้วยวิธีของเซิร์ฟเวอร์นั้น หากเปลี่ยนพอร์ตใน `.env` ให้แก้ `proxy_pass` ให้ตรงกัน
5. ทดสอบสมัคร เรียน ส่งไฟล์ สอบ ตรวจงาน พิมพ์ใบประกาศ และ callback ThaID ด้วยข้อมูลทดสอบก่อนเปิดรับผู้เรียน

ค่า cookie `Secure` อ้างอิง `APP_URL` และไม่เชื่อ header จาก client โดยอัตโนมัติ ฐานข้อมูลไม่เปิดพอร์ตออก host; web bind เฉพาะ loopback ให้ reverse proxy รับ HTTPS

ปัจจุบัน rate limiting ใช้ IP ที่ Apache เห็น หลัง reverse proxy อาจรวมผู้ใช้ไว้ใน bucket เดียวกัน ให้ตั้ง `mod_remoteip` เฉพาะ proxy ที่เชื่อถือได้บนเครื่องจริงก่อนเปิดใช้งานจำนวนมาก อย่าเชื่อ X-Forwarded-For จากผู้ใช้ทั่วไป

### Error 500 หลังอัปเดต source วิดีโอแนะนำ

ฐานข้อมูลเดิมไม่ได้สร้างตารางใหม่จาก `schema.sql` ซ้ำโดยอัตโนมัติ ต้องรัน `bin/migrate.php` บนเซิร์ฟเวอร์ด้วย PHP CLI และค่าการเชื่อมต่อฐานข้อมูลของระบบจริง สำหรับ `compose.production.yaml` ให้ build image ใหม่ก่อน เพราะไม่ได้ mount source จาก host:

```sh
docker compose -f compose.production.yaml up -d --build web
docker compose -f compose.production.yaml exec -T web php bin/migrate.php
```

หลังแก้ไขนี้ เมื่อไม่มีตารางวิดีโอ หน้าแรกยังเปิดได้ ส่วนหน้าจัดการวิดีโอจะแจ้ง 503 พร้อมคำแนะนำให้อัปเดตฐานข้อมูล การเพิ่มวิดีโอต้องรัน migration ให้สำเร็จก่อน หากยังเกิด 500 ตรวจ `docker compose -f compose.production.yaml logs --tail=80 web` (หรือ PHP error log ของโฮสติ้ง) บันทึก log ระบุชนิดข้อผิดพลาด รหัส และตำแหน่งไฟล์ โดยไม่แสดงรายละเอียดฐานข้อมูลแก่ผู้เข้าชม

### MP4 บน Plesk ขึ้น 422 ขณะอ่านความยาว

`app/Upload.php` อ่านความยาวจาก `moov/mvhd` ของ MP4 โดยตรง รองรับ movie header รุ่น 0/1 และขนาด atom แบบ 32/64 บิต จึงไม่จำเป็นต้องเปิด `shell_exec` หรือติดตั้ง ffprobe สำหรับ MP4 ทั่วไป อ้างอิงโครงสร้าง [movie header ของ Apple](https://developer.apple.com/documentation/quicktime-file-format/movie_header_atom) อ่านเฉพาะ header โดยข้าม payload และจำกัดจำนวน atom ที่ตรวจ

หากอ่าน header ไม่ได้ จะลอง ffprobe เมื่อ PHP อนุญาต ถ้ายังอ่านไม่ได้ จะแจ้งให้นำไฟล์ไปบันทึกเป็น MP4 ใหม่หรือตรวจ ffprobe แยกจากข้อความวิดีโอยาวเกิน 12 ชั่วโมง ไม่ใช้ความยาวที่ผู้ใช้กรอกแทนความยาว MP4 ที่ตรวจไม่ได้ อัปเดตไฟล์ `app/Upload.php` บนเซิร์ฟเวอร์แล้วอัปโหลดใหม่ได้ ไม่ต้องเปลี่ยนฐานข้อมูล

ทดสอบจำลองโฮสติ้งที่ปิด shell execution:

```sh
docker compose -f compose.test.yaml exec -T web php -d disable_functions=shell_exec tests/upload_duration.php
```

### Plesk: POST วิดีโอเป็น 500 และ log มี SQL code 1064

คำสั่ง shared lock ใช้ `LOCK IN SHARE MODE` แทน `FOR SHARE` เพื่อรองรับ syntax ของ MariaDB และ MySQL โดยคง lock ภายใน transaction อัปเดต `app/DepartmentVideo.php`, `app/Category.php`, `app/EditorImage.php` และ `app/CertificateDesign.php` ไม่ต้องแก้ schema

หากมี warning `open_basedir` จากการตรวจ `/opt/vekec-vendor/autoload.php` ให้แก้เฉพาะบรรทัด require ใน `app/bootstrap.php` เป็น:

```php
require (is_file(dirname(__DIR__).'/vendor/autoload.php') ? dirname(__DIR__).'/vendor' : '/opt/vekec-vendor') . '/autoload.php';
```

คงค่า `putenv` สำหรับฐานข้อมูลและค่า production บนเซิร์ฟเวอร์ไว้ทั้งหมด บนโฮสติ้งต้องมี `vendor/autoload.php` ของโปรเจคในตำแหน่งที่ PHP อ่านได้ การเลือก local vendor ก่อนจะไม่ตรวจพาธ `/opt` เมื่อมี local vendor อยู่ ไม่จำเป็นต้องปิดหรือขยาย open_basedir ทดสอบกรณีนี้ด้วย `docker compose -f compose.test.yaml exec -T web php tests/bootstrap_autoload.php`

### ออกแบบและกำหนดเลขที่เกียรติบัตรแนะแนว

ดู [คู่มืออัปเดต Plesk และการใช้งาน](docs/guidance-certificates-plesk.md) ใช้ migration `010_guidance_certificates` หรือ Import `database/guidance-certificates.sql` ผ่าน phpMyAdmin แล้วเปิด **ออกแบบเกียรติบัตรแนะแนว** และ **เลขที่เกียรติบัตรแนะแนว** ในส่วนผู้ดูแล เครื่องมือออกแบบใช้ชุดเดียวกับเกียรติบัตรหลัก รองรับตรา/ลายเซ็นและผู้บริหาร โดยเก็บการตั้งค่าแยกจากหลักสูตร แบบเริ่มต้นสืบทอดตราและลายเซ็นจากระบบหลัก ต้องเพิ่มและเปิดใช้ชุดเลขของงานแนะแนวก่อนออกใบใหม่ ใบเดิมยังคงรูปแบบเดิม

### ตั้งค่าการแสดงผลหน้าแรกและหน้ารวมวิดีโอแนะนำ

ผู้ดูแลเปิด `/admin/homepage` เพื่อเปิด–ปิด 4 ส่วนบนหน้าแรกได้แยกกัน โดยค่าเริ่มต้นเปิดครบทุกส่วน วิดีโอแนะนำบนหน้าแรกแสดงล่าสุดไม่เกิน 3 รายการพร้อมลิงก์ดูทั้งหมดที่ `/department-videos` (สาธารณะและแบ่งหน้า) หน้ารายวิชาทั้งหมด `/courses` ใช้งานได้แม้ซ่อนส่วนค้นหารายวิชาบนหน้าแรก การตั้งค่าจัดเก็บในตาราง `settings` เดิม ดู [คู่มือ Plesk](docs/homepage-settings-plesk.md)

การ์ดวิดีโอทั้งหน้าแรกและหน้ารวมแสดงยอดเข้าชมและยอดผู้รับเกียรติบัตร รัน `php bin/migrate.php` เพื่อเพิ่ม migration `011_department_video_views` ก่อนใช้งาน ยอดเข้าชมเริ่มเก็บหลังอัปเดต นับเมื่อเปิดหน้าวิดีโอที่เผยแพร่หนึ่งครั้งต่อวิดีโอต่อเซสชันเบราว์เซอร์ การรีเฟรช โหลดไฟล์ และ heartbeat ไม่นับเพิ่ม ยอดเกียรติบัตรนับจากรายการที่ออกจริงของวิดีโอนั้น รวมรายการเดิมก่อนอัปเดต การขอซ้ำด้วย watch token เดิมไม่นับเพิ่ม และการแก้ไข/ซ่อนวิดีโอไม่ล้างยอด
